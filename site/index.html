What Relay is

Relay is a personal music server and a set of clients for it, in the same spirit as Plex, Jellyfin or Nextcloud but built for music. You run the server, you point it at your own audio files and only you and the people you invite can reach it. There is no central Relay service, no catalog and no account owned by anyone but you. The app ships empty and plays only the music you host.

You own everything

Your library, database and covers live on your server. Nothing is sent to a third party by the app.

Reach it anywhere

Stream from a browser, a Windows desktop app, Android and Android Auto. Downloads play offline.

Made for music

Tag based library scan, embedded cover art, synced lyrics with translations, gapless queue, shuffle and repeat.

Social, if you want

Friend activity, listen along and Chorus collaborative sessions. All scoped to the people on your server.

How it works

Relay is three parts that run together. A server holds your library and does the streaming. A web app is the admin panel and a browser player. Native apps talk to the same server directly.

Server

An Express and TypeScript API with a Postgres database. It scans your files, streams audio with seeking, transcodes on the fly and handles auth, playlists, likes and the social features.

Web app

A Next.js app that is both the admin interface and a full browser player. It also acts as the same origin proxy so a browser only ever talks to your own domain.

Apps

One Flutter codebase builds the Windows desktop app and the Android app. Background playback, lock screen controls, Android Auto and offline downloads are built in.

In a typical deployment a Cloudflare Tunnel is the only way in. It reaches the web container which proxies the API over an internal network. No database port and no API port is exposed to the public internet.

Host your own server

Everything runs in containers. The only thing you install on the host is Docker. Clone the repo, set a few values and bring it up.

  1. Get the code

    Clone the repository from GitHub onto the machine that will host your music.

    git clone https://github.com/AGNIV03/Relay.git
cd Relay

  2. Create your config

    Copy the example environment file and edit it. At minimum set MUSIC_DIR to the folder that holds your audio and set strong secrets.

    cp .env.example .env
# then edit .env (see the Configuration table below)

  3. Bring it up

    Build and start the containers. The database migrates itself on first start and the first admin account is created from your config.

    docker compose up -d --build

  4. Scan your library

    Open the web app, sign in with the admin account, then trigger a library scan from the admin page. Your tracks, albums and cover art appear once the scan finishes.

Using it without a domain

A domain is optional. Relay works fine on a home network or over a private tunnel. Pick whichever fits you.

On your home network

Run it on a machine at home and reach it by that machine's local address, for example http://192.168.1.20:3000. Set NEXT_PUBLIC_API_URL to that address. Good for listening on the same network.

On the same machine

For a quick trial, run it and open http://localhost:3000 in your browser. Nothing leaves the machine.

A free tunnel from anywhere

A Cloudflare Tunnel gives you an address that works away from home without opening any ports on your router. This is the recommended way to reach your server on the go and it needs no static IP.

A private mesh

A tool like Tailscale puts your phone and your server on the same private network. Reach the server by its mesh address with nothing exposed to the public internet.

The Android and Windows apps ask for a server address on their first screen. Enter whichever address you chose above, then your username and password. Because Relay is self-hosted there is no default address, each person points their app at their own server.

Adding and managing music

Relay reads standard audio files and their tags. There are two ways to get music in.

Drop files into your music folder

Put audio into the folder you set as MUSIC_DIR, organised however you like. Then run a scan from the admin page. Relay reads the tags, pulls embedded cover art and builds the artist and album views. Rescans are incremental so later scans only pick up what changed.

Upload from inside the app

You can also upload tracks from the web app and the desktop app. Uploaded files land in your music folder and are added to the library. Large files upload in chunks so they are not blocked by size limits.

Users and sharing

The admin creates accounts. Everyone who signs in shares the same library and can build their own playlists, likes and profile.

Accounts

The first admin is created from your config. Admins manage users and trigger scans from the admin page. Passwords are stored hashed on your server.

Playlists and likes

Each user has their own Liked Songs and playlists. Playlists can have collaborators so a few people can build one together.

Friend activity

See who is online and what they are playing or last played. It updates in well under a second.

Listen along and Chorus

Play a friend's music on your own device kept in sync or run a Chorus session where several people control one shared queue.

Everyone on a server can see shared content. The music library is shared across all accounts on that server. Profiles, activity and public playlists are visible to other users on the same instance. Only invite people you are happy to share with. See the privacy notes for detail.

Apps

One codebase, several places to listen.

Browser

A full player built into the web app. Nothing to install, works on any device with a browser.

Windows

A desktop app with background playback and media key controls. It keeps playing in the tray when you close the window.

Android

Background playback, lock screen and notification controls, Android Auto and offline downloads that play with no connection.

Android Auto

Relay is a full media app in the car. Connect your phone and Relay appears in the car's app list. The media card shows your last played song with its progress the moment you connect, so you can pick up where you left off without touching your phone.

What works in the car

Browse your library

Four tabs, Home, Playlists, Songs and Recents. Home leads with Liked Songs and Most Played, then your playlists. Tap anything to play it with its full context queued.

Resume on connect

The media card shows the last song you played with its saved position, paused and ready. Press play and it picks up from there.

Voice

Say a command like "play Fireflies" while Relay is active and it searches your library and plays the best match. An empty request plays your recent music.

Search

Use the car's search to find a song by title, artist or album. Results are ranked so the closest match leads.

Voice with a named app. "Hey Google, play a song on Relay" works in the car and with the classic Google Assistant on the phone. On phones where Gemini is the assistant, music routing to third-party apps is limited by the assistant itself, which is outside the app's control.

Offline and background

Download songs and playlists to your device and they play with no connection, even when you are signed out. Playback keeps going in the background with lock screen and media key controls. The queue supports shuffle and repeat.

Security posture

Relay is built to sit safely on the public internet behind a tunnel.

One way in

Container ports bind to loopback or are not published at all. The tunnel is the only ingress so nothing is reachable on the host's public address.

Auth

Short lived access tokens with refresh, passwords hashed with bcrypt and a refusal to seed a weak admin password in production.

Rate limiting

Login and refresh are rate limited to blunt brute force, on top of your tunnel provider, with a cap on held long-poll connections.

Headers and CORS

Security headers and a content security policy on the web app, with a default-deny cross-origin policy on the API.
